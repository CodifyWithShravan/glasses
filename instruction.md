This document outlines the current architectural state, hardware diagnostics, and codebase configurations for K. Dhruv Tej's integrated ESP32-S3 IoT camera and audio project, preparing it for handoff to the Antigravity AI agent. The system consists of an ESP32-S3 microcontroller handling an OV2640 camera stream and MAX98357A I2S audio output, paired with a custom native Android client designed for local network streaming.

Hardware Diagnostics & Thermal State
The OV2640 camera module is currently experiencing a severe thermal anomaly, exceeding 80°C during operation. Multimeter diagnostics performed on the 24-pin FPC connector confirmed that the ESP32-S3 motherboard's voltage regulators are healthy and delivering clean power: AVDD (Pin 4) is at 2.8V, DOVDD (Pins 10/11) is at 3.3V, and the XCLK (Pin 13) is registering ~1.65V (indicating a proper 50% duty cycle PWM clock). The overheating is isolated to a hardware short within the camera ribbon module itself (likely a blown decoupling capacitor or die gate damage from a prior reverse-power event). The module requires physical replacement to prevent motherboard damage.

ESP32-S3 Firmware Configuration
To temporarily mitigate the hardware thermal stress, the firmware's camera_config_t has been throttled: the xclk_freq_hz was reduced from 20MHz to 10MHz, and the resolution was lowered to FRAMESIZE_QVGA (320x240). The firmware heavily utilizes non-blocking millis() timing patterns to prevent stalling the video stream. This includes logic for an onboard WS2812B NeoPixel (GPIO 48) using neopixelWrite(), which is programmed to remain completely off for the first 60 seconds after boot, followed by a 500ms interval toggle state. Additionally, a MAX98357A I2S audio amplifier has been integrated. It is wired to the ESP32-S3 using BCLK on GPIO 15, LRC on GPIO 16, and DIN on GPIO 7. Volume control is managed through a combination of the MAX98357A's hardware GAIN pin strapping and software-based 16-bit PCM sample scaling using the ESP32-audioI2S library.

Android Application & Custom Network Routing
The companion Android application consumes the ESP32-S3's local MJPEG stream ([http://192.168.4.1:81/stream](http://192.168.4.1:81/stream)) via a native WebView configured for an edge-to-edge display (scrollbars disabled, black background, loadUrl() implementation, and android:usesCleartextTraffic="true" enabled in the Manifest). Because the ESP32 acts as a local Access Point without internet access, standard Android routing drops the connection and falls back to cellular data. To bypass this, the app implements a custom ConnectivityManager network callback using NetworkRequest.Builder(). The app filters for TRANSPORT_WIFI with NET_CAPABILITY_INTERNET explicitly removed, and targets the ESP32's specific SSID using WifiNetworkSpecifier. Once connected, the application executes connectivityManager.bindProcessToNetwork(network) to forcefully route all socket and WebView traffic through the ESP32's local interface, automatically loading the stream on the main UI thread.
